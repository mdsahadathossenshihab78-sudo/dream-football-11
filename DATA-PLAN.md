## Tested sources
No external data sources. All game content (teams, players, prices) is original authored game data defined in code — fictional club names, country-named national teams with generic color badges, and fully fictional player names, per the IP boundary set in the parent conversation. No network fetch at runtime.

## Imagery
- One decorative stadium-night illustration for the Home hero background, generated with media.generate_image into client/src/assets (drawn/painted style, no real stadium, no logos, no text). All other visuals are CSS/canvas: player cards use jersey-number/initial medallions (fictional players have no photos — no photo sourcing attempted, by design).

## Long-term data behavior
- **Refresh policy**: none; no external data. Profile/coins/squad/tournament state load from the artifact DB on open.
- **Growth**: one profile row per account (keyed by email), owned-player rows per purchase, tournament state as one JSON row per profile.
- **Ordering**: store sorted by rating desc; squad shown in formation order.
- **Time semantics**: match rewards computed server-side from the reported result with caps; no wall-clock-sensitive data.

## Rejected approaches
- **Real club names/crests and real player names/photos**: rejected — Konami/club/player IP; the parent conversation already committed to an original game with its own teams and players.
- **Real Gmail OAuth login**: rejected — not available inside the artifact sandbox; account is created in-app with name + email, which matches the user's 'new Gmail → new account → starter team' flow.
